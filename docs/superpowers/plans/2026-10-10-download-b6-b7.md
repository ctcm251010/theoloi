# B6/B7 production download and verification plan

> **For agentic workers:** Use superpowers:executing-plans inline; one final fresh review. Track steps below.

**Goal:** Actually process all 983 catalog assets to verified local M4A with durable resume/retry state; stop before B8/B9.

**Architecture:** Enumerate immutable catalog into deterministic semantic paths. SQLite WAL/FULL state records attempts and evidence, while media operations use checked local HLS manifests, temporary output, probe/full decode/hash and atomic publication. A single-process lock prevents overlapping batches; two worker threads each own a DB connection. Completed outputs are validated against fingerprints and on-disk hashes before skipping; interrupted publication is recovered from retained verification evidence.

**Tech stack:** Python standard library, SQLite, existing FFmpeg/FFprobe, jsonschema validator, unittest.

**Spec:** User B6/B7 attachment `7632049b-0b3c-4514-bdef-86af0ddda00e/Pasted text.txt` and existing B4/B5 report.

## Constraints

- No catalog edits; baseline SHA-256 `e449b3a25ed49c6879bf06c72219863857632491f4a2ca424c2bc692e45ca8d4`.
- 485 guide + 485 instrumental + 13 meditation; namespace by logical section/number or silent audio ID.
- AAC streamcopy, M4A/ipod muxer, faststart; no transcode or forced sample rate/bitrate.
- Final file published only after remux/probe/decode/hash PASS. Failed partials remain in per-asset temp workspace until retry replaces them; never mark them completed.
- Max three attempts for transient failures per retry round, backoff 2/4 seconds; no retries on access/encryption/schema/profile failures. HTTP 429/503 pauses scheduling rather than hammering the origin.
- Default concurrency 2, configurable 1–4; no authentication headers/cookies/tokens or bypass.
- Separate `state/transfers.sqlite`, operational `state/download-summary.json`, log and report; no delivery manifest or cloud/API/web/bot work.
- User explicitly authorizes the implementation and actual full run after tests. Rights confirmation requested because the user's final condition limits processing to authorized media; offline implementation proceeds while awaiting that information.
- No Git repository: keep existing workspace and document execution; Git worktree/commit/merge helpers do not apply.

## Review focus

- Crashes between verifying, rename and completed commit must preserve either a recoverable verified file or a pending job, never false completion.
- Completed state with missing/tampered output or different fingerprint must not skip.
- Ctrl+C must stop submission, terminate active children safely and preserve resumability.
- Permanent auth/encryption failure must not retry/bypass; transient failure must stop after its finite budget; rate limit must stop new scheduling.
- Existing final files without reliable evidence must be fully verified before adoption or quarantined, never skipped by filename.
