# AudioTP — B10 preflight, mapping review, desktop architecture

User authorizes autonomous implementation and offline tests for A/B, analysis only for C. No additional design approval pauses. Existing workspace has no Git repository; no worktrees/commits or project restart. Never read real credentials, run live B10, mutate audio/upload state/R2 or fetch BookVN media.

## A — Independent remote audit preparation

Keep existing user-run verify-r2.py CLI. Test real inventory/head/report logic with synthetic S3 responses and a real botocore request-event guard before transport. Cover LIST pagination/token/key anomalies, duplicate expected identities, missing/extra objects, metadata/size/type/ETag, 403 permanent and bounded 429/5xx retry, interruption and report persistence/redaction. Only allowed S3 operations LIST/HEAD, no GET/write/state access. Robust malformed responses must FAIL, never false PASS. Hash means metadata-match only; no remote content checksum claim.

## B — Review store

Use an append-only event overlay in reviews/, rather than mutate generated catalog, snapshot or SQLite transfer state. JSON atomic replacement plus OS lock, revision and per-event hash chain; immutable history with reviewer, UTC time, evidence, provenance reference, exact source/audio IDs, identity fingerprints and catalog hashes. Not a cryptographic signature of a human: file owner can rewrite it; this is an audit trail and consistency check.

Approve/reject/defer decisions apply to a source/audio pair; unmatched sources may be deferred with null audio. One active approved audio song per source. A later reject/defer suspends that pair; changing approved song requires explicit rejection first. Do not approve automatically by confidence. Many distinct source records may link to one song; never merge duplicate titles/editions.

Every apply requires explicit reviewed=true and human evidence/provenance. Batch is dry-run by default, maximum 50 decisions, revision/catalog pins and exact --confirm-count to apply atomically. Stale identity fingerprints fail closed at export; rights changes never become identity approval. Keep all source rights unchanged, including restricted. Export verified identity links only, with rights copied as context, not a serveable catalog. No music/content/legal verdict generated by Codex.

Read-only priority queue: main464 first, then five duplicate appendix pairs (10 sources), then other conflicts/unmatched/candidates. Lightweight local HTML embeds metadata with escaped JSON/textContent/CSP, has no server/network/media, lets a human select decisions and download a batch proposal. CLI dry-run/import is the only store writer. Proposal is not an approval until explicitly imported. Static HTML preferred over a write-capable localhost server to reduce attack surface; CLI-only remains usable.

## C — Desktop proposal

Compare Tauri/WebView2, Windows .NET + WebView2 and Electron from official current docs. Recommend a small Windows client; private R2 behind authenticated controlled Worker API, no R2 keys in app, authorized catalog filtering, Range/HEAD for seeking, bounded private cache, no forced full library download. Discuss runtime vs installer sizes without invented benchmark numbers, signed updates, Windows support, future PDF after rights/source review. No app/API/deployment code or Cloudflare changes.
